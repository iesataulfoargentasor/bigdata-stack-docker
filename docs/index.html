Stack de Big Data en Docker

Guía paso a paso para desplegar en tu equipo un ecosistema completo de ingeniería de datos con un único fichero de Docker Compose.

Clúster Hadoop del profesor y herramientas del stack docente de ingeniería de datos.

Hadoop 3.3.6MinIO Hive 4.0.1Trino 476 DuckDB 1.3dltdbt Airflow 2.10

Qué vamos a montar

Cuatro capas: orquestación, motores, catálogo y origen y almacenamiento + cómputo. HDFS y MinIO conviven a propósito para comparar el enfoque clásico (cómputo junto al dato) con el moderno (object storage).

Si usas Windows

  • Docker Desktop con el motor WSL 2 activado.
  • El disco virtual de Docker en una unidad con espacio: Settings → Resources → Advanced → Disk image location.
  • Memoria suficiente para WSL. Crea o edita %UserProfile%\.wslconfig y reinicia con wsl --shutdown:
[wsl2]
memory=10GB
processors=6
Ojo con docker-scout. Tras construir imágenes, Docker Desktop analiza vulnerabilidades con este proceso, que puede ocupar varios GB de RAM y dejar el equipo sin memoria. Si todo va muy lento, búscalo en el Administrador de tareas.

Si usas un Mac con chip Apple

Funciona, pero las imágenes de Hadoop y Hive sólo existen para amd64 y se ejecutan emuladas (más lentas). El resto es nativo.

1Clonar el repositorio

git clone https://github.com/iesataulfoargentasor/bigdata-stack-docker.git
cd bigdata-stack-docker

Para no repetir -f docker-compose.stack.yml en cada orden, indícale a Compose qué fichero usar:

$env:COMPOSE_FILE = "docker-compose.stack.yml"
export COMPOSE_FILE=docker-compose.stack.yml
export AIRFLOW_UID=$(id -u)    # sólo Linux: Airflow y el lab escriben con tu usuario
El resto de la guía asume que has definido COMPOSE_FILE. Si no, añade -f docker-compose.stack.yml detrás de docker compose.

3Arrancar

# Escenario lago
docker compose --profile lake up -d

# o escenario ELT
docker compose --profile elt up -d
La primera vez descarga unos 12 GB de imágenes (profesorbigdata/*:v2.0 en Docker Hub) y el tiempo depende de la conexión. Las siguientes veces arranca en 2-3 minutos. --build sólo hace falta si has modificado un Dockerfile y quieres reconstruir la imagen en tu equipo.

Qué está pasando

Los servicios arrancan en cadena: cada uno espera a que el anterior esté healthy.

  nn[namenode] --> dn[dnnm] --> hi[hdfs-init] --> hms[hive-metastore] --> hs2[hiveserver2]

5Primera prueba: el lago

Abre la consola de Trino:

docker exec -it trino trino

Y ejecuta estas sentencias. Trino escribe Parquet, registra la tabla en el metastore y la vuelve a leer:

-- En HDFS
CREATE SCHEMA hive.demo WITH (location = 'hdfs://namenode:9000/user/hive/warehouse/demo.db');
CREATE TABLE hive.demo.nation WITH (format = 'PARQUET') AS SELECT * FROM tpch.tiny.nation;
SELECT count(*) FROM hive.demo.nation;      -- 25

-- En MinIO
CREATE SCHEMA hive.minio WITH (location = 's3a://warehouse/minio.db');
CREATE TABLE hive.minio.region WITH (format = 'PARQUET') AS SELECT * FROM tpch.tiny.region;
SELECT count(*) FROM hive.minio.region;     -- 5

-- Federación con MySQL
SELECT c.customer_city, count(*) AS pedidos
FROM mysql.retail_db.orders o
JOIN mysql.retail_db.customers c ON o.order_customer_id = c.customer_id
GROUP BY 1 ORDER BY 2 DESC LIMIT 5;

El catálogo es compartido: lo que crea Trino lo ve HiveServer2.

docker exec -it hiveserver2 beeline -u "jdbc:hive2://localhost:10000/" -e "SHOW DATABASES; SELECT count(*) FROM demo.nation;"
✅ Si ves 25 desde Trino y desde Hive, el lago funciona: HDFS, MinIO, metastore y los dos motores.

A mano, en el nodo lab

docker exec lab python /workspace/dlt/mysql_to_duckdb.py
docker exec -w /workspace/dbt/retail lab dbt run
docker exec -w /workspace/dbt/retail lab dbt test
docker exec lab duckdb /workspace/data/retail.duckdb -c "SELECT * FROM main_marts.ventas_por_ciudad LIMIT 5;"

Con Airflow

  1. Entra en localhost:8082 con admin / admin.
  2. Activa el DAG elt_retail con el interruptor de la izquierda.
  3. Pulsa ▶ Trigger DAG y sigue las tareas dlt_mysql_a_duckdb → dbt_run → dbt_test.
DuckDB admite un único proceso escribiendo. Si un cuaderno del lab tiene abierto retail.duckdb, la tarea de Airflow fallará hasta que cierres esa conexión.
✅ Si las tres tareas terminan en verde, el ELT completo funciona.

7Apagar, encender, reiniciar

Quiero…Comando
Apagar al terminar la clase (conserva todo)docker compose --profile all stop
Encender en la siguiente sesióndocker compose --profile lake start
Cambiar de escenariodocker compose --profile lake stop y docker compose --profile elt up -d
Ver logs de un serviciodocker compose logs -f trino
Recargar retail_dbdocker compose run --rm retail-init python /workspace/init/retail_init.py --force
Borrar contenedores (los datos quedan)docker compose --profile all down

Usa stop/start en el día a día. Que los contenedores de Hadoop queden en Exited (137) tras un stop es normal.

8Repetir el acceso de aula con Tailscale

Recordatorio para volver a dar el stack a la clase. El equipo de casa es un Ubuntu 24.04 con Tailscale ya instalada: la misma IP 100.x del escritorio remoto. Desde el aula (Windows 11, Windows 10 o Ubuntu 22.04 LTS Desktop) solo se consultan los puertos del stack en esa IP. Sin abrir el router. Sin RDP ni SSH.

Tailscale crea la red privada entre ese Ubuntu y los PCs del aula. Funciona con CG-NAT y cuando el instituto solo deja salir por el 443. Cada consola se abre como en local, cambiando localhost por la IP 100.x de casa, no por la IP de la LAN del aula.

No abras los puertos del stack en el router de casa y no expongas RDP (3389) ni SSH. Las contraseñas son las de clase (admin, minioadmin, retail) y Jupyter no pide token. Cualquiera en Internet podría borrar HDFS o lanzar trabajos.

Casa (Ubuntu 24.04)

Tailscale ya está instalada por el escritorio remoto: no la reinstales. Comprueba que sigue conectada y anota la IP. Esa IP es el destino de la política.

tailscale status
tailscale ip -4

El equipo tiene que seguir encendido durante la clase. Evita la suspensión: en logind, IdleAction=ignore y HandleLidSwitch=ignore; en el escritorio, sleep-inactive-ac-type en nothing.

sudo mkdir -p /etc/systemd/logind.conf.d
printf '[Login]\nIdleAction=ignore\nHandleLidSwitch=ignore\n' | sudo tee /etc/systemd/logind.conf.d/nosleep.conf
sudo systemctl restart systemd-logind
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing'

Política en el editor de grants

La cuenta es personal (Gmail), plan Free. En la consola abre el editor de grants (el JSON de la política actual). No uses las ACL antiguas. La política por defecto, «allow all», dejaría RDP y SSH visibles en la tailnet: no sirve. Tus equipos siguen entrando a todo; los del aula, solo a los puertos del stack. Pega este JSON y sustituye 100.x.x.x por la IP real:

{
  "tagOwners": { "tag:aula": ["autogroup:admin"] },
  "grants": [
    { "src": ["autogroup:member"], "dst": ["*"], "ip": ["*"] },
    {
      "src": ["tag:aula"],
      "dst": ["100.x.x.x"],
      "ip": [
        "tcp:9870", "tcp:9864", "tcp:8088", "tcp:8042",
        "tcp:9000", "tcp:9001", "tcp:8080", "tcp:8888",
        "tcp:8889", "tcp:8082", "tcp:10000", "tcp:10002",
        "tcp:9083", "tcp:3306", "tcp:3307"
      ]
    }
  ]
}

9870 es el NameNode, 9864 el DataNode, 8088 el ResourceManager, 8042 el NodeManager, 9000 y 9001 MinIO, 8080 Trino, 8888 el JupyterLab del laboratorio, 8889 el Jupyter del cliente Hadoop, 8082 Airflow, 10000 y 10002 HiveServer2, 9083 el metastore, 3306 el MySQL del metastore y 3307 el MySQL de retail.

Los alumnos comparten un solo stack. Lo que uno borre en HDFS, en MinIO o en Airflow lo ven todos. Sirve para mirar las consolas y probar una configuración; no para que cada uno monte su propio clúster.

Clave para los alumnos

En Settings → Keys genera una auth key con Reusable en ON, caducidad de 90 días, Ephemeral en OFF y Tags en ON con la etiqueta tag:aula. La descripción sola no aplica la etiqueta: tiene que quedar marcada en Tags. No la subas al repositorio ni la pegues en un chat. Aquí se escribe siempre como LA_CLAVE.

Una clave anterior quedó expuesta en un chat. Si sigue activa, revócala en la consola y genera otra.
No ejecutes la clave tag:aula en el Windows del profesor. Ese equipo ya tenía --exit-node-allow-lan-access. Un tailscale up sin ese flag o sin --reset falla y no debe cambiar la identidad de ese PC.

Alumnos: Windows 11 y Windows 10

PowerShell como administrador:

winget install tailscale.tailscale
Restart-Service Tailscale
tailscale.exe up --auth-key=LA_CLAVE --unattended

Si no hay winget, descarga el instalador oficial de Tailscale y sigue desde Restart-Service.

No pulses «Log in» de la interfaz gráfica: el equipo entraría con otra cuenta y sin la etiqueta tag:aula.

Añade --reset solo si el comando exige flags de una sesión anterior. Si tailscale status muestra NoState, el servicio no está arriba o todavía no hay sesión: Restart-Service Tailscale y repite el up.

Comprueba con tailscale status y abre en el navegador http://IP_DE_CASA:PUERTO. La IP es la 100.x de casa, no la de la LAN del aula.

Alumnos: Ubuntu 22.04 LTS Desktop

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --auth-key=LA_CLAVE

Si el equipo ya está en otra cuenta: sudo tailscale logout y después sudo tailscale up --auth-key=LA_CLAVE. Comprueba con sudo tailscale status y abre la misma URL http://IP_DE_CASA:PUERTO.

?Problemas frecuentes

docker compose up no arranca nada

Falta el profile. Usa --profile lake, --profile elt o --profile all.

The container name "/namenode" is already in use

Está levantado el clúster mínimo (docker-compose.yml), que usa los mismos nombres. Apágalo con docker compose -f docker-compose.yml down y repite.

Ports are not available: 8080, 3306…

Otra aplicación usa ese puerto: Kafka UI (8080), un MySQL instalado en el equipo (3306)… Párala o cambia el puerto publicado en docker-compose.stack.yml.

namenode unhealthy / dependency failed to start

El equipo va justo de recursos. Espera un minuto y repite el mismo up -d. Levanta lake y elt por separado en vez de all.

Trino: hive-metastore:9083 Read timed out

El metastore aún no está listo o el equipo está saturado. Comprueba con docker compose ps que hive-metastore está healthy y reintenta.

Trino: Partition location does not exist

Un CREATE TABLE … AS se interrumpió y quedó la tabla registrada sin datos. Haz DROP TABLE y vuelve a crearla.

Airflow: Cannot open file "/workspace/data/retail.duckdb"

Lo tiene abierto un cuaderno del lab, o (en Linux) AIRFLOW_UID no coincide con tu usuario. Cierra la conexión del cuaderno y define export AIRFLOW_UID=$(id -u) antes del up.

Docker Desktop: Internal Server Error

Casi siempre es disco lleno. Libera espacio (docker system df, docker image prune) o mueve el disco de Docker a otra unidad.

Clúster Hadoop y adaptación: IES Ataúlfo Argenta, Big Data Aplicado.

Stack docente: credenciales triviales y permisos abiertos. No lo expongas a Internet.
